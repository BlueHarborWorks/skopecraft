01 / Thesis

Define the decision

Write one thesis that every product claim must help answer.

Determine whether any product, module, or realistic combination in each vendor portfolio can identify a human or AI agent and control that actor’s specific action across local endpoints and protected data paths.

Research question. Can the portfolio connect actor identity to a specific command, API call, file operation, browser action, or data movement event; apply policy at the point of action; and produce evidence that the control worked?

02 / Chain

Test the complete control chain

A product can contribute to the thesis without completing it. Record exactly where each capability enters and leaves the chain.

Actor identityHuman, service, local agent, autonomous agent, device, workload.
Action visibilityCommand, process, API operation, file access, browser event, data transfer.
Policy decisionConditions join identity, context, resource, intent, and risk.
EnforcementAllow, block, constrain, require approval, isolate, or remediate.
Investigation & proofAnalytics, incident timeline, reporting, logs, evidence, and outcome.
Level 4Complete capability

Connects the defined chain end to end for the target domain.

Level 3Partial capability

Covers a meaningful subset, path, subject, or activity with explicit limits.

Level 2Visibility / response

Observes or investigates without producing the required control outcome.

Level 1No demonstrated capability

No primary evidence ties the product to the decision under study.

03 / Guard

Hold the scope line

Use this section as an editorial gate before adding any product or claim.

In scope
  • Identity attribution for the target human or AI actor
  • Policy over the target command, action, file, API, browser, CLI, SDK, or data path
  • Inline enforcement and approval controls
  • Command centers, advanced analytics, incident management, reporting, and logging when they prove or investigate the target action
  • Product combinations that form a realistic supported control path
Out of scope unless directly connected
  • Generic AI guardrails, prompt filtering, model probes, and red teaming
  • Generic posture, asset discovery, endpoint blocking, or network security
  • Broad MCP, A2A, or tool authorization without the target action path
  • Marketing category claims without action-level evidence
  • Adjacent features that do not control, investigate, or prove the core action
Equivalence rule Do not treat indirect prevention as equivalent to action-level control. State the exact governed step, its dependency on the target workflow, and what remains outside policy.

05 / Evidence

Make every conclusion auditable

Use current primary sources and distinguish verified behavior from unresolved boundaries.

1 · Product and admin documentationConfiguration, policy fields, enforcement semantics, logs, and supported paths.
2 · Release notes and lifecycle recordsAvailability, preview status, regional limits, entitlement, and version dates.
3 · Official product announcementsUse for new capability framing; verify operational details in documentation.
4 · Secondary analysisUse for discovery or context; do not let it carry a decisive capability claim.
Claim
The exact factual statement this evidence supports.
Source
Page title, publisher, direct URL, and access date.
Quote
Short supporting passage or exact configuration field.
Status
Current / GA / Preview / Unverified / Requires tenant validation.
Boundary
What the source does not establish.
Freshness
Source date, corpus refresh date, and any known documentation lag.

Acceptance checklist

Every section answers the core thesis.
Each product is tied to a supported capability path.
Every stage in the defined capability chain is assessed separately.
Indirect controls are labeled with their dependency and boundary.
Analytics and incident functions support a thesis-relevant event.
Primary citations are current and directly support the claim.
Preview, entitlement, region, and tenant-validation limits are explicit.
The conclusion states full, partial, visibility-only, or absent control.
